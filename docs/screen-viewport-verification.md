## 旧约束与新模式

旧约束探针只把独立合成节点设置为 `min-width:1280px; min-height:660px`，
放入与当前工作区同尺寸的离屏父容器，读取 `scrollWidth / scrollHeight` 后立即删除。
它没有复制企业业务实现，也没有模拟全部 382px 侧栏、210px 底栏或业务断点。
报告每条记录均标注“合成旧约束探针，非实际业务系统运行结果”。
40 组中 18 组至少存在一方向溢出；该数字不能解读为实际业务系统故障率或修复率。

新响应式夹具按工作区宽高划分顶部、左右和底部区域，中部使用 `minmax(0, 1fr)`，
不足的列表只在局部滚动，较低容器切换为紧凑间距。40 组均满足：

- 根滚动范围没有超出实际逻辑视口超过 1px。
- 顶部工具、风险、统计、图例、趋势图均位于工作区内，无相邻面板严重遮挡。
- 浮层字号至少 12px；地图不使用 CSS transform，地图中心点击仍可到达引擎。
- 图表 Canvas 非空，实际渲染尺寸与容器边界差小于 2px，允许 Canvas 整数尺寸差异。

局部画布设计尺寸为 1280 × 720。以下结果 Dev / Build 均通过，
局部宿主 `clientWidth / clientHeight` 为整数，不等同于外部工作区的小数边界：

| 策略    | Zoom | 局部可用尺寸 | 画布实际尺寸     | 局部滚动范围 |
| ------- | ---- | ------------ | ---------------- | ------------ |
| contain | 80%  | 1568 × 752   | 1336.89 × 752.00 | 1568 × 752   |
| contain | 150% | 821 × 332    | 590.22 × 332.00  | 821 × 332    |
| width   | 80%  | 1568 × 752   | 1568.00 × 882.00 | 1568 × 882   |
| width   | 150% | 821 × 332    | 821.00 × 461.81  | 821 × 462    |

contain 保持完整比例并留白；width 保持比例与宽度，超出高度只在宿主内部滚动。
两者根节点均无 transform，根字号 16px、body 字号 14px 不变。
画布使用可配置字号下限，并对按钮、选择器显式保留最小点击高度，
8 组均验证真实点击计数递增，而不是仅检查 CSS 声明。
`disabled` 和 `responsive` 亦在本夹具覆盖；`vw` 变量与构建转换由对应单元和构建测试覆盖，
不把它们宣称为本次 48 组浏览器矩阵的额外已测模式。

## 浮层、地图与缓存证据

Element Plus Select 和 Tooltip 采用默认 Teleport，Dialog 使用 `append-to-body`。
脚本读取弹层打开后的触发器边界，避免按宽度模式局部滚动后使用旧坐标。
检查下拉与 Tooltip 和触发器相邻、弹层仍在视口内，点击选项和按钮确实生效。
Dialog 等待入场变换结束后测量实际 `.el-dialog` 面板，不能用全屏遮罩边界冒充弹窗尺寸；
局部画布弹窗按钮仍为 14px，未继承设计画布字号反算。

排查过程中发现：在入场动画内挂载 `max-height` 表格时，Element Plus 的
`el-table__inner-wrapper / el-scrollbar__wrap` 触发过原生 ResizeObserver 循环通知。
仅延后挂载仍不足。夹具最终在 `opened` 后挂载表格，并给示例的局部滚动区明确 240px 高度，
避免内容反向计算弹窗高度。真实表格与列头断言保留，未关闭 Observer 或过滤错误消息。
最终报告没有此通知；排查记录保留在本地 `output/release/viewport-observer-diagnostic.json`。
这是明确尺寸弹窗的集成示例，不是强制所有业务表格固定 240px 的框架规则。

地图先通过真实双击把 View 从 zoom 3 改为 4，并产生非零中心坐标，
随后全部尺寸变化和工作台 → 系统管理 → 工作台缓存切换保持原实例、中心与 zoom。
实例 ID 来自模块级递增序号，重建会产生不同 ID，不是每次 setup 重新归零的假计数。
40 组的地图坐标正反算最大点击误差为 `1.2710574864626038e-13` CSS px。
该精度针对脱敏矢量夹具，不代表私有图层、投影或所有业务热点已验收。

ECharts 使用真实按需引擎与 Canvas；容器尺寸变化只调用现有 `resize()`。
地图只调用现有 `updateSize()`，没有因尺寸变化重建实例或发送业务请求。
系统页面关闭适配后保持 14px 字号与普通布局，返回工作台后选择器与地图状态恢复。
源码分别位于 `src/main.ts`、`src/pages/ScalePage.vue`、
`src/components/MapSurface.vue` 和 `src/components/TrendSurface.vue`，均相对夹具根目录。

## 截图与性能数据

真实浏览器缩放会改变页面 DPR，而 Playwright context 的固定 DPR 不随 `tabs.setZoom` 更新。
本轮改用 CDP `Page.captureScreenshot` 捕获浏览器原生表面，
设置 `captureBeyondViewport:false`，没有按旧 DPR 裁切或补白。
20 张响应式生产截图的 PNG 尺寸均与校准窗口内容尺寸一致，
另有 4 张局部 contain / width 生产截图，全部为 1280 × 720。
原始 `screenshotSize`、DPR、inner/outer 尺寸和组件矩形都写入 JSON，不能只凭截图推断根因。

| 环境  | 地图实例 / 图表实例   | 地图 resize 前 → 后 | 图表 resize 前 → 后 | 静止观察 |
| ----- | --------------------- | ------------------- | ------------------- | -------- |
| Build | 1 / 2，各一份在用实例 | 26 → 26             | 27 → 27             | 400ms    |
| Dev   | 1 / 2，各一份在用实例 | 23 → 23             | 24 → 24             | 400ms    |

实例编号并非实例数量；两种环境的当前 DOM 都各有一个地图和一个图表。
总 resize 次数受浏览器调度与首测影响，不以 Dev/Build 之间的次数差推断性能优劣。
静止窗口计数不增长证明本次观察中没有持续 resize 循环，不是 CPU、内存或长时间泄漏基准。

本次主门禁中的 Vite 构建输出为 446ms，转换 2354 个模块；这是该次构建器报告值，
不是独立冷启动基准，也不是整轮浏览器矩阵耗时。不复用第4轮 15.40s 或更早 457ms 的计时，
也不根据不同轮次的单次构建耗时宣称性能提升。原脚本未记录整轮 wall-time，
因此不补造该数值、不把自动化点击延迟当算法耗时、不宣称真实项目性能提升。
夹具入口 JS 约 1135.23kB / gzip 375.66kB，CSS 约 365.03kB / gzip 49.63kB，
显式包含 Element Plus、OpenLayers 和 ECharts，构建器给出大 chunk 警告。
这些是集成验收工具的产物，不是 Blank/Screen 基础模板或视口包体积，不能据此提高公共预算。

## 消费项目仍需处理

省级平台需要在自身分支调整固定最小宽高、侧栏/底栏尺寸协调、业务断点、
地图留白和图层点击热区，并保留颜色、地图和业务行为回归。
公共包不应硬编码行业面板、地图请求或企业接口。地图和图表实例应由业务层维护，
组件尺寸回调不应重新拉取全部数据或重建引擎。
后台系统管理、登录权限和复杂混合路由仍须使用对应验收门禁，
此脱敏视口夹具不能代替真实后端、真实业务升级和最终部署验证。
